# Phase 02 picker runner source archive — consumer 5095 / runtime a6

This is the exact independently reviewed task-runner source for the dated picker campaign, archived with repository-relative file names and SHA-256 bindings. It makes the external fixture mechanism inspectable. It is **not** a portable/current-head installer: original task-local paths and identities remain in the source as provenance; required host context/targets are deliberately not provisioned here. Do not substitute this archive for current final-head verification.

The app creates an original marked synthetic `accounts.json` in private Application Support. Private placement is intentional: the native document picker cannot browse it directly. A host-side adapter observes the printed own-nonce fixture path, validates the fixture marker/path/version/name and copies its bytes once into a picker-visible location. Android uses `run-as` for the isolated verification package and exclusive creation in Download; iOS uses only the attested disposable simulator's local Files provider. Both verify the copied SHA-256 and preserve the original. Only the operator/CUA selects the copy and explicitly confirms replacement/recovery; no helper injects UI input.

The Android adapter reuses the reviewed stage runner with explicit source/root/cwd adaptation, strict prebuilt APK and existing-fixture preservation checks, and a direct host integration driver. It performs no uninstall fallback. The iOS adapter's Flutter installer is explicitly confined to its disposable simulator; `--no-uninstall` alone is not preservation protection. Entry point, imported support, engine, guard, builder/adapter and driver hashes are separate bindings in the manifest. New source/engine/guard epochs require a newly reviewed plan and bindings, not silent reuse of 5095/a6.

No executable fixture payload, APK, app bundle, normal account data, target descriptor, signing file, raw device log or VM authentication URL is included. The copied source files have unchanged bytes. The original campaign's accepted/failing native receipts remain separately source-scoped; an inspectable runner is not proof that a pending native case passed.
