## App contracts and observable behavior

- **Route catalogue:** `sales`, `sale-history`, `inventory`, `expenses`, `statement`, `suppliers`, `invoices`, `materials`, `payments`, `cash`, `categories`, `settings`. Unknown/missing last route falls back to Sales. Retired `savings` is never displayed; its shortcut becomes empty. Other invalid IDs must not create a route. Six slots preserve reference order, empty choices and duplicate-choice behavior; no invented uniqueness rule. Defaults: sales, inventory, sale-history, expenses, cash, settings.
- **Persisted schema v1:** one app-owned snapshot containing `schemaVersion`, `lastRouteId`, and exactly six string shortcut IDs. Namespace `dakhl_restaurant.shell.v1`. No form contents, active ticket, account identity, amounts, preferences from later settings workflows or focus objects are serialized. App parsing normalizes known retired/unknown IDs; malformed structure or newer schema is reported and retained without silently overwriting it. No migration reads legacy accounts or the Phase 00 probe.
- **Bootstrap coordination:** expose Initializing / Ready / ProtectedReadFailure states in the shell ViewModel. During the first asynchronous read, gate navigation/shortcut mutations and do not queue implicit saves. A valid/absent read establishes the revision and enables normal interaction. Unavailable, corrupt or newer-schema data leaves persistence and shortcut editing disabled; show a retryable warning and allow session-only navigation using safe defaults without writing the protected store. A retry carries a request generation and session-intent generation: ignore stale responses, and never replace a route selected since that read began. On successful retry, adopt the stored slots/revision, retain newer session intent, and require a subsequent explicit navigation/edit action to persist it; read completion itself never auto-saves. Dispose cancels/invalidates outstanding reads.
- **Read/save flow:** absent snapshot uses reference defaults. Successful navigation persists the accepted destination; canceled dirty-form navigation saves nothing. Shortcut edits remain a draft until Save. Serialize changes and await engine commit before showing Saved. Definitively failed writes preserve the last acknowledged snapshot; a distinct unknown-commit outcome requires reread before retry. Failed saves retain current edits and expose retry/cancel; visible route can remain open with an unsaved-preferences warning. On revision conflict, reread and report the conflict instead of overwriting another snapshot. A retry after uncertain completion first checks whether the same payload already committed.
- **Restart guarantee:** after an acknowledged successful save, stop the process and start a fresh process against the same isolated database; last route and all six slots must restore offline. Restoring a frame/provider/OS restoration bucket is additional coverage, not the cold-start test. Unacknowledged interruption can restore the old or new complete snapshot; power-loss, uninstall/clear-data and account recovery guarantees are not introduced here.
- **Interaction state:** app ViewModels hold session form/ticket presentation state separately from route views. Navigating away/back preserves a synthetic active ticket in the session; canceling discard retains edits. Durable ticket recovery belongs to Phase 04. Session undo dispatch targets local edit/session actions only; native text undo retains text-field ownership. No posted financial reversal is implemented. Search/shortcut/checkout key bindings route through guarded commands; checkout uses a synthetic callback, never posting a sale.
- **Accessibility/layout:** Arabic RTL reading/semantic order; Latin tabular numbers; labels/errors and status announcements; visible focus, disabled/busy semantics, keyboard trap/return, hidden-menu exclusion, mobile back and reduced-motion compatibility. Match 390×844 reference, verify 320 width at 200% text, 1024×768, 1440×1000 and 1920×1080. Real keyboard insets/safe areas must leave save/cancel reachable. Invoice examples prove dialog structure only, not Phase 08 functionality.
